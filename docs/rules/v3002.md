# V3002 — unresolved-reference

> **Caution — intentionally incomplete.** Without a Verse/UEFN API database or
> cross-file analysis, a name the scope graph cannot resolve may still come
> from UEFN, another file, or a Verse builtin this tool does not know. A false
> `unresolved` finding is a bug, not a feature. Projects adopting this rule
> should first run a **report-only job with `--select V3002`**, review the
> findings, and add known external names to `[lint] external-names` before
> considering any stronger gate.

V3002 reports a reference only when the complete local scope graph cannot
resolve it, it has no receiver, it is outside an extension-function receiver
position, and it is not in the built-in or project allowlist. The rule is
opt-in, has warning severity, and never offers a fix. It makes no claim that the
Verse compiler would reject the name.

## Exclusions and completeness

- If any unsupported name-bearing construct makes `is_complete()` false, the
  rule reports nothing from the file. This fail-closed behavior applies even to
  otherwise ordinary references elsewhere in that file.
- `Obj.Member` does not report `Member`: the object's type is unknown. The
  object expression itself is still analyzed as an ordinary reference, so an
  unresolved `Obj` can be reported. `self.Member` is also excluded from V3002;
  member lookup is not ordinary lexical lookup.
- Extension-function receiver types and module-scoped paths are not reported.
  Paths and constructs that the graph cannot model make it incomplete and keep
  V3002 silent.
- Names resolved in any enclosing function, block, `for`, `if`, class, module,
  or file scope are not reported. Resolution follows the scope graph's
  declaration-order and shadowing rules: a self-reference resolves, while a
  use before a later declaration in the same scope does not resolve to that
  future declaration.

## External names

The built-in allowlist is deliberately short. Each entry is treated as
external for the stated reason:

- `Print` — Verse's built-in output function; projects do not declare it in
  their source files.
- `Sleep` — Verse's built-in suspending function; projects do not declare it in
  their source files.
- `GetSimulationEntity` — supplied by the UEFN `creative_device` base API, not
  declared in the local source file.

Add project-specific names with an exact, case-sensitive list of strings:

```toml
[lint]
select = ["V3002"]
external-names = ["ProjectApi", "ImportedHelper"]
```

The default is an empty list. These entries only silence matching unresolved
references; they do not create bindings or affect other rules. Any name not in
the built-in set or this list remains unresolved when the graph is complete.
Empty entries are rejected. Do not use this rule as proof that a name is absent
from an API or project.

## Diagnostic and shared controls

There is one `V3002` warning per eligible unresolved reference. Its range spans
the identifier only, its message is the fixed string
`Reference is not declared in a modeled local scope`, and it is not fixable.
The rule is off by default. Enable it with `--select V3002`, the semantic-family
prefix `--select V3`, or `--select V`. Severity overrides, `--ignore`, line
suppression, and `--show-suppressed` use the shared rule machinery.
