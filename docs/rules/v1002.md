# V1002 — missing-final-newline

Default on; error; safe fix available. Purpose: consistent text-file termination.
This is a tool style policy, not a compiler error.

Detect a nonempty body (excluding initial UTF-8 BOM) not ending in LF/CRLF,
after strict syntax/protected-span validation. Diagnostic is an empty range at
EOF. Empty input and BOM-only input are clean. A whitespace-only nonempty body
without newline is reported. Unterminated strings/comments are execution errors,
not V1002 findings.

Bad: `A := 1` at EOF. Good: the same bytes followed by newline. A closed comment
without final newline is reported; the fix appends outside its protected bytes,
including a final line comment. Existing CRLF is retained; no-newline inputs
use LF. Fix plus V1001 converges even when trailing whitespace reaches EOF.

File-level rule: line suppression is forbidden and fails with exit 2. Use
config/CLI ignore V1002 if intentionally omitting a final newline.
