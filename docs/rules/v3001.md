# V3001 — unused-declaration

Opt-in; warning; no safe fix. Purpose: find a declaration a refactor left behind
without grepping by hand. This is a semantic rule built on the
[scope graph](../semantic-model.md), not a compiler rule, and it is never
selected by default because its false-positive cost is higher than its
convenience.

Report a binding that has **zero resolved references** in the file's scope graph.
Exactly one finding is emitted per binding, spanning the binding's **name range
only** — not the whole declaration — so the position points at the thing a human
would remove. The message is the fixed English string `Declaration is never
referenced`: the identifier is already in the source range, so embedding it would
make output less deterministic and harder to grep.

## What is reported

- a `var_declaration` local inside a function body with no resolved reference;
- a `constant_declaration` local inside a function body with no resolved
  reference;
- a function `parameter` with no resolved reference — **only** when
  `[lint] unused-parameters = true`.

## What is never reported

- **Anything at all, when the graph is incomplete.** If the model recorded any
  construct it could not classify, the file's graph has `is_complete() == false`
  and this rule emits nothing — no diagnostic and no execution error — under
  every configuration. An "unused" claim from a graph that could not see a use
  would tell a user to delete live code, which is worse than silence.
- **Exported bindings.** Cross-file reachability is out of scope for this wave,
  so intra-file usage proves nothing about a name other files can use. A
  `public` or `protected` specifier on the declaration makes a binding exported,
  and any top-level `class` / `struct` / `interface` / `enum` name is treated as
  exported because it is the module's public surface.
- **`_`-prefixed names**, the conventional "intentionally unused" marker. This
  applies to locals and to parameters, in both parameter modes.
- **`using` imports.** An import can be re-exported, and the grammar does not let
  this model trace every name a package path binds, so an untraceable import is
  treated as used rather than unused.
- **`for` iterator and `if` condition bindings.** The bound value is tested or
  iterated by the construct that binds it, which is not evidence that the
  declaration is dead. These constructs also clear `is_complete()` whenever their
  body cannot be walked, so the exclusion is asserted twice.
- **File-scope, class-member and module-level bindings.** They are reachable from
  elsewhere in the project; only a function-body local is provably local to the
  code this graph sees.
- **An assigned-but-unread local.** Resolution counts every reference, including
  a write target, so this rule proves "no reference at all", never "no read".
  That is deliberately weaker than it could be: a write is a use this model can
  see, and guessing intent from it would produce exactly the false positive this
  design is built to avoid.

## Parameters

`[lint] unused-parameters` selects between the two behaviours:

```toml
[lint]
select = ["V3001"]
unused-parameters = true # default false
```

With the default `false` a parameter is never reported, because an unused
parameter is usually dictated by a callback or interface signature rather than
left behind. With `true` an unused parameter is reported under the same
exclusions as above, so a `_`-prefixed parameter stays silent either way.
`--show-config` prints the resolved value.

## Selecting it

The rule is off by default. Enable it with `--select V3001`, with the family
prefix `--select V3`, or with the whole registry through `--select V`. Everything
else is inherited from the shared rule machinery and is not special-cased here:
`[lint.severity]` may promote it to `error`, `--ignore V3001` removes it, a
`verse-lint: disable-next-line V3001 -- reason` directive on the finding's line
suppresses it, and `--show-suppressed` lists it again. A warning exits 0 unless
`--deny-warnings` is set.

## No safe fix

There is none, by design. Deleting a declaration is a semantic change a human has
to judge, and an "unused" result computed from an incomplete graph would delete
live code. The rule is `fixable: false` in the registry, so `--fix` never touches
it.
