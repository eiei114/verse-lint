# V2002 — bare-todo-comment

Opt-in; warning; no safe fix. Purpose: require a reference for TODO work rather
than inventing an owner/ticket. This is a tool/team policy, not a compiler rule.

Within lexer-confirmed line/block comments, match uppercase `TODO` whose
neighbor characters are neither Unicode alphanumeric nor underscore. Lowercase
`todo`, `TODOS`, `_TODO`, `TODO_` and `日本TODO語` are not markers. Combining marks
are not alphanumeric under this boundary definition. Strings are not comments.

Accept an immediately following `(`, non-whitespace reference text, and the
first `)` before any physical newline. Bad: `TODO`, `TODO()`, `TODO(  )`, or a
reference spanning lines. Good: `TODO(PROJ-123): work`, `TODO(参照)`.
Multiple markers are checked independently. No URL/issue existence lookup or
arbitrary regex executes. A valid suppression directive's entire line comment,
including its reason, is excluded from this rule to avoid self-referential TODOs.

Use either line directive with a reason or config/CLI ignore. Findings within
multiline comments use each marker's physical line. Automatic fixing is unsafe
because the tool cannot choose a real ticket/owner.
