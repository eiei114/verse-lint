# V1004 — space-indent-width

Opt-in; warning; **no safe fix**. Purpose: catch space indentation that is not a
multiple of the width the project configured, which produces content no
formatter round-trips predictably.

## The width is configured, never inferred

`[lint] indent-width` states the width, default `4`, accepted range `1..=16`. The
tool never guesses it: not from the file's most common indentation, not from a
tab's visual width, not from a neighbouring line. V1003 already refuses to
interpret a tab's width for the same reason — a wrong guess silently changes
block ownership — and this rule inherits that stance rather than relaxing it.
An out-of-range or non-integer value is a configuration error with exit 2, even
when V1004 is not selected, exactly as an out-of-range `max-line-length` is.

## Detection

A line is reported when all of the following hold:

- the leading whitespace run sits at the physical start of a line, and
- the line is outside every open parenthesis, bracket and brace (`depth == 0`),
  the same predicate V1003 uses, and
- the line carries at least one token that is neither trivia nor a comment, and
- the run contains **only spaces** and its length is not a multiple of
  `indent-width`.

Exactly **one** diagnostic per offending line, spanning the whole leading space
run. The range starts at the first byte of the line's indentation, so the
reported columns are the run's own columns.

With the default `indent-width = 4`, a two-space or six-space structural indent is
reported and a four-space or eight-space indent is clean. With `indent-width = 2`
those cases flip: two, four and eight spaces are clean, six is reported.

## What is not reported

- **A run containing a tab.** That line belongs to [V1003](v1003.md), which reports
  the whole run; the two rules share one predicate and split on the tab byte, so
  no line is ever reported twice.
- **Blank lines and whitespace-only lines.** There is no code, and trailing
  whitespace is [V1001](v1001.md)'s job.
- **Continuation lines inside an open bracket**, whose depth is non-zero. Their
  alignment is a layout choice, not a block-nesting statement.
- **Comment-only lines**, and spaces inside strings, character literals and
  comment interiors: those are literal bytes, not indentation.
- **Files the run could not analyze.** Unsupported or incomplete syntax stays an
  execution error with exit 2 and no V1004 finding.

Good: `f():void =` followed by four or eight spaces before `Print("x")`.
Bad: the same line indented by two or six spaces.
Counterexamples: `\tPrint("x")` (V1003's), `    # note` (comment-only), a blank
line, and `A := array{` / `        1,` (a delimited continuation).

## No safe fix

Both repairs change block structure: adding spaces can create a new nesting level
that the author never wrote, and removing them can collapse a level that the
compiler was reading. Neither is a whitespace-only edit the tool can validate, so
this rule is `fixable: false`, `--fix` never touches it, and no tab width is ever
interpreted. Rendering as a warning rather than an error is deliberate: a
project that has not settled on a width should not be blocked by a lint rule it
did not select.

## Severity and default

`warning`, and **not** selected by default. Enable it with `--select V1004`, with
the `--select V1` or `--select V` families, or in `[lint] select`. Once selected,
a warning exits 0 unless `--deny-warnings` is set, or `[lint.severity]
V1004 = "error"` raises its severity. Severity never selects a rule.

Everything else comes from the shared rule machinery: `--ignore V1004` /
`[lint] ignore` removes the rule, `--show-config` prints the effective severity
and the resolved `indent-width`, and JSON/SARIF/GitHub output derive metadata from
`rules::REGISTRY`, where SARIF `defaultConfiguration.enabled` is `false`.

## Suppression

A line directive on the **diagnosed line** suppresses it:

```text
# verse-lint: disable-next-line V1004 -- generated snippet, width preserved
   A := 1
```

`disable-line` also works when the indentation and the directive share a physical
line, and `--ignore V1004` (or `[lint] ignore = ["V1004"]`) removes the rule for
the whole project. Like every other rule, a directive needs a nonempty
` -- reason`.
